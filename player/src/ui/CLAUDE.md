# UI: guide for agents

`player/src/ui/` renders one screen at a time. Neutral UI wording only; repair text comes from the bundle (hard rule 1).

Read first: `docs/decisions.md`, section "Experience".

- **ui/** renders one screen at a time with `h()` from `dom.ts`. `flow.ts` has every journey screen; one card component serves inspections, steps and checks. `#root[data-view]` names the screen (`journey:card:<id>`); the e2e tests and `window.__app` (the App) rely on it.
- **Navigation:** `App.backTarget()` says what Back does on the current screen (null on the main tabs); the arrow, the edge swipe (`ui/edge.ts`) and the browser's back (`popstate`; the app keeps one history entry while it can go back) all call `App.goBack()`. On a card, Back (button, arrow key, swipe down, edge swipe) is `Journey.backCard()`: it undoes the card's answer and goes to the previous card. The progress bar is vertical, left of the text.
- **Card column** (`flow.ts`, comment above `COL`): the text box is one snapping scroll column with the previous card, the current one and the next one (dimmed), drawn from `Journey.peekBack` / `peekNext`. Native scrolling moves between them (touch, touchpad, wheel); when it rests on a neighbour the journey moves there. A card waiting for an answer shows only the top of the next card (`locked`, springs back). From card to card `patchCard` updates the screen in place (`App.render` tries it first), so the text box stays in the page; don't rebuild it per card, or touchpad gestures stall again. The 3D view follows the scroll (`showAhead`): it shows a neighbour card as soon as letting go would land there; the move itself waits for the rest. While the column scrolls to a new card by itself, rests are ignored (`COL.moving`). Most e2e journeys run with reduced motion (no smooth scroll); `extras/laptop-wheel` runs with motion, so test scroll changes there.
- **Assistant button:** `ui/assistant.ts`, one button on every screen. Drag it; it sticks to the left or right edge and `store.data.assistant` keeps `{ side, y }`. `placeAssistant` moves it (not saved) out of the way of `PROTECTED` buttons and, where possible, text; add a selector there when a new screen has a button it must not cover. One element serves every screen (`assistantButton` keeps it), so it slides only when its place changes; a new element would slide in from the CSS default.

## Known gaps

- The edge swipe works from the first 24 px of the left edge only. Safari on iOS has its own edge swipe there; the app keeps a history entry so that swipe also goes back in the app, and ignores a browser back within 0.7 s of its own swipe. Chrome on Android uses a system gesture the page never sees; it goes through the same history entry.
- Moving between cards works with touch, touchpad and wheel over the text, not over the 3D view and not with a mouse drag. Headless Chrome does not snap after CDP touch events, so the column also settles by itself 0.35 s after a touch ends (`settle`); the e2e test relies on that. Mouse wheel is tested in a laptop context (`extras/laptop-wheel`); the emulated phone gets no wheel events.
